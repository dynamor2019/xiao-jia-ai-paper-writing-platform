# Research Workbench

把论文任务作为一个可检查、可复用的研究空间来推进。协调者负责范围、术语规范化、证据冲突和最终综合；专项 skill 只完成当前阶段的工作。

## 研究空间

开始前检查并维护以下对象，缺失项必须显式标记，不得用推测补齐：

- `research-brief.md`：研究问题、对象、范围、目标期刊、预期贡献和不主张的边界。
- `claim-evidence-matrix.md`：核心主张、证据来源、数据/结果位置、支持强度、冲突和缺口。
- `analysis-plan.md`：数据、变量、方法、基线、对照、消融、敏感性、统计和验收标准。
- `.dsh-state/corpus-memory.json`：按文件哈希保存的语料摘要、证据定位、方法、局限和引用键；命中时禁止重复读取全文。
- `paper-working.md`：按段落即时保存的唯一工作稿检查点。
- 质量报告与导出产物：必须保留并可追溯到对应源稿版本。

如果用户已有命名文件，沿用现有文件，不制造平行副本。

## 生命周期

1. **研究建档**：把用户输入视为宽泛领域，记录目标期刊、资源、限制和完成定义。
2. **联网选题**：先检索最新原始论文和权威学术元数据，再用当前可用最高能力模型比较至少三个方向的创新性、科学价值、可证伪性、数据可得性、成本与失败风险；保存搜索证据，确认方向前不写正文。
3. **系统取证**：形成检索式、纳排标准、文献笔记和主张-证据矩阵；关键主张优先绑定原始论文，不用综述替代决定性证据。
4. **冻结方案**：明确假设、变量、数据与样本、基线、对照、消融、敏感性、统计功效、不确定性、泄漏防护、伦理、停止规则和验收标准；变更必须留痕。
5. **程序实验**：实现或审查实验程序，先冒烟测试再完整运行，固定种子并保存环境、命令、日志、失败运行与机器可读结果；程序失败不得推进状态。
6. **三重数据验收**：依次执行结构完整性、科学/统计合理性和从原始输入独立复算；任一步失败都修复来源或代码并从第一步重跑，禁止手工改结果。
7. **证据锁定**：冻结结果 SHA256，生成验证历史和 `result-provenance.tsv`；当前文件与 PASS 哈希不一致时禁止任何正文写作。
8. **正文成稿**：数据门禁后才开始引言和方法；先生成真实图表和表格，再逐段报告效应量、不确定性、基线、消融、敏感性及失败结果，不把观察写成解释。
9. **讨论成稿**：把解释与结果、文献和理论逐项对应，处理替代解释、外部效度、局限和不主张边界。
10. **稿件完备**：补方法、结论和摘要，核对报告规范、作者贡献、伦理、利益冲突、数据/代码可用性及 AI 使用声明。
11. **独立校验**：写作者不得自行宣布完成；运行引用、理论、实验、统计、图表、复现、结构及 DOCX 门禁，阻断项必须返回证据、数据或代码修复。
12. **发表闭环**：执行期刊适配、投稿包、编辑初审模拟、投稿记录、审稿意见分解、修订追踪和逐条回复，直至最终决定归档。

## 路由

只加载完成当前步骤所需的最小技能组合：

- 主张规划与引用：`claim-evidence-matrix`
- 统计与实验：`statistical-reporting`、`computational-reproducibility`
- 图表：`scientific-figures-tables`
- 逐段成稿：`paper-writer`
- 完成审查：`paper-quality-gate`、`submission-readiness`
- Word 交付：`word-export`
- 期刊适配：所选 `journal-*` skill
- 研究伦理与声明：`research-integrity`
- 返修与回复：`response-to-reviewers`

### 社会科学 / 经济学实证论文附加路由

当研究包含观察数据分析、政策评估、因果推断或计量建模时，按阶段加载：

| 当前阶段 | 加载 skill |
|---------|-----------|
| 文献综述（含系统综述 / PRISMA） | `literature-review` |
| 识别策略选择（DID / IV / RD / SCM / DML） | `causal-inference` |
| 预注册 / PAP 冻结 / 数据合约 | `computational-reproducibility` |
| 运行 Python 实证流水线（清洗→建模→出表出图） | `empirical-analysis-pipeline` |
| 实证章节写作与系数意义解释 | `aer-paper-sections` |
| 报告效应量、因果措辞、稳健性描述 | `statistical-reporting` |
| 引用逐条核验与台账 | `citation-integrity` |
| 投稿前一致性审计 + 模拟审稿 | `pre-submission-review` |
| 投稿前降低 AI 写作信号 | `de-aigc` |

**实证论文阶段门禁顺序**（与生命周期步骤 1–12 对应）：

```
步骤 2  联网选题  ─────────────────────────────────→  literature-review（系统检索）
步骤 3  系统取证  ─────────────────────────────────→  literature-review（综合与空白识别）
步骤 4  冻结方案  ─────────────────────────────────→  causal-inference（策略选择 + strategy.md）
                                                       computational-reproducibility（PAP + 数据合约）
步骤 5  程序实验  ─────────────────────────────────→  empirical-analysis-pipeline（8 步流水线）
步骤 6  三重数据验收  ────────────────────────────→  computational-reproducibility（三重校验）
步骤 8  正文成稿（定量段落）  ───────────────────→  statistical-reporting（效应量 + 识别假设报告）
步骤 15 引用 + 润色  ────────────────────────────→  citation-integrity（逐条核验）→ de-aigc（如需降低 AI 信号）
步骤 16 质量校验  ───────────────────────────────→  pre-submission-review（一致性审计）→ paper-quality-gate
步骤 18–20 格式 + 导出 + 投稿  ─────────────────→  submission-readiness + word-export
```

实证论文的数据门禁与正文写作顺序不变；上述分支 skill 是对步骤 4–8 的细化，不替代现有生命周期结构。

## 状态纪律

- “计划中”“运行中”“已保存”“已校验”“可投稿”是不同状态。
- 只有真实工具运行或文件写入可以推进状态；自然语言承诺不计为进度。
- 任务列表与模型运行状态分开判断；模型停止但检查点存在时，从最后一个已保存段落恢复。
- 质量报告必须保留稳定问题编号。一次修复一个阻断项，重新运行相关门禁，再更新状态。
- `topic-discovery.md`、`analysis-plan.md`、成功实验日志、机器可读结果、三重数据验收与结果溯源是全部正文写作的前置门禁。
- 投稿不等于发表；投稿编号、编辑决定、审稿意见、修订版本和最终决定必须作为独立状态记录。
- 工作流可以保存和复用，但复用时必须重新核对研究对象、输入版本、目标期刊和验收标准。
- 读取已有语料前必须先查询 `research_memory`；只有 MISS、STALE 或需要核对精确原文时才读取源文件，读取后立即更新 memo。

## 文件版本规则

工作台展示的是 canonical 状态，不鼓励堆文件。除“题目确认、方案冻结/修订、数据哈希变化、正式评审轮次、投稿导出、投稿后返修”外，所有进展都更新现有 milestone 文件，不新建同义副本。若某阶段需要记录历史，用 `milestones/change-log.tsv` 和文件内小节记录，不用 `v2/final/fixed/revised` 文件名制造多个候选版本。工作台只把 canonical 文件点亮；发现同一产物多个变体时，应提示保留一个并清理其余草稿。
