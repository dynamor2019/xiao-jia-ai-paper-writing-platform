# 学术论文质量门禁

## 0.1.7 门禁分层与执行优先级

- 以当前作者批准的研究范围和 DSH PaperPipeline 实际检查点为准；下面的10阶段是写作检查视角，不替代平台的实际阶段。
- 科学缺陷：计算错误、虚构实测、隐藏失败或未知结果、引用不支持原句、无证据的肯定结论，必须阻断；严重指控必须引用当前稿件原文并绑定证据或具体缺失义务。
- 编辑建议：措辞、重复和非误导性排版问题记录为待办，不因 `Minor Revision` 阻断科学稿件；严重误导性图表仍须阻断。
- 投稿事项：已如实披露的公开数据权限、作者声明和实时期刊格式单独待作者确认；允许交付明确状态的本地稿件，不得标为投稿就绪。
- 条件数值案例、探索性研究和负结果不必支持初始假设；按实际执行方法和证据评价，不要求它未声称的工程认证、基线优越性或普适稳健性。
- 主观评分不能替代科学证据；项目明确规定的文献数量、近期比例、主题覆盖和知识综合是强制交付门禁，与科学有效性审查分别执行，不能降级为建议。
- 自相矛盾或无原文证据的审查属于审查响应异常；最多一次有记录的独立复核，仍无有效意见则停止，不自动通过、不清缓存、不重置付费改稿限额。
- 用户已授权自动执行时，逐段保存后自动推进；只在真实科学阻塞、资源限额、重要方向决策或作者声明时请求输入，不要求每段再次点击继续。
- 文献工作分为两个环节：正式检索与精读在实验结果验收之后、大纲和正文写作之前，根据真实方法、负结果和解释边界选文献；格式检查与交付前核验检查来源是否真实、是否支持正文、近期比例及分布是否合适，不在核验阶段检索或代写。经典奠基文献不因年份较早自动删除。选题阶段的预检索仅支撑问题和方案，不替代结果后的正式检索，也不允许事后悄改原假设。

## 核心原则

1. **证据优于声称** — 所有引用必须可追溯，所有数据必须可验证，审查结论必须基于证据而非"应该""看起来"
2. **流程优于即兴** — 门禁未开不推进，结构未定不写作
3. **确认优于假设** — 关键节点必须用户确认，避免大规模返工
4. **绝不编造** — 找不到真实文献就少引用，绝不编造作者、标题、DOI、数据
5. **AI是副驾驶不是机长** — AI负责检索、格式化、验证、检查；研究问题、方法论、解读由用户主导

## 完整流水线（10阶段）

### Stage 1 — 研究规划与选题确认
**目标：** 明确研究问题、论文类型、目标期刊/会议

**操作：**
1. 与用户对话确认：
   - 论文类型（期刊/会议/学位论文/综述）
   - 目标期刊或会议（IEEE/ACM/Elsevier/Springer等）
   - 研究主题与核心问题
   - 技术路线与方法
   - 预期贡献
   - 引用格式（APA/IEEE/Chicago/MLA/Vancouver）
   - 语言（中文/英文/双语）
2. 生成结构化问题树 → 保存到 `plan/problem-tree.md`
3. 进行假设辩论（Proponent vs Skeptic），检验研究问题的合理性

**门禁：** 用户确认研究简报（RQ Brief）后才能进入下一阶段

---

### Stage 2 — 深度文献检索
**目标：** 收集至少15篇高相关性论文，建立知识基础
**执行位置：** PaperPipeline 的 `data-validation` 完成后执行 `literature-search` 和 `literature-review`，然后才进入大纲及正式正文；后续格式核验是独立环节。

**操作：**
1. 使用 web_search 多轮检索：
   - 核心关键词组合（至少5组不同关键词）
   - 高被引论文追踪（citation chaining）
   - 最新论文（近2-3年）
   - 经典奠基论文
2. 对每篇论文提取**知识卡片**：
   ```
   标题 | 作者 | 年份 | 期刊 | 核心方法 | 主要发现 | 与本研究关系 | 引用价值
   ```
3. 按主题分类 Related Work
4. 识别研究空白（research gaps）
5. 保存到 `related-work.md` 和 `papers/*.json`

**门禁：** 至少15篇高相关性、可核验的独立研究论文；文档、软件说明、手册和重复引用不计入论文数量。研究论文近期比例至少30%，需分布到主要证据章节，并完成主题综合、方法比较及主张-证据绑定。数量不足时由DSH继续定向检索和补强，不编造、不用弱相关条目凑数，不把引用存在性通过当成交付完整性通过。

---

### Stage 2.5 — 知识综合与完整性验证 I（强制门禁，不可跳过）
**目标：** 综合文献，验证研究基础的完整性

**操作：**
1. 文献按主题/方法聚类
2. 识别文献间的矛盾和分歧
3. 按影响/可行性/相关性排序研究缺口
4. 明确本研究定位
5. **7模式AI故障检查清单**（工作流内部检查，不代表已核验的外部标准）：
   - [ ] 实施bug — 方法描述是否有逻辑错误
   - [ ] 幻觉结果 — 是否有无法验证的声称
   - [ ] 方法论编造 — 方法是否真实存在且合理
   - [ ] 引用幻觉 — 所有引用是否真实存在
   - [ ] 捷径依赖 — 是否跳过了关键论证步骤
   - [ ] 框架锁定 — 是否局限在单一框架无法质疑
   - [ ] 过度自信 — 是否对不确定的事情过于肯定

**输出：** `plan/research-gaps.md` + 完整性验证报告

**门禁：** 已证实且未解决的重大科学缺陷阻断；SUSPECTED 必须指出原句和证据并核实，不能把未核实的怀疑自动当成错误，也不能用用户确认覆盖真实诚信缺陷。

---

### Stage 3 — 大纲生成与论文结构
**目标：** 生成详细的论文章节大纲

**操作：**
1. 基于研究问题和文献综合，生成详细大纲：
   - 每章节的核心论点
   - 每段落的内容要点
   - 引用分配（哪段引用哪篇文献）
   - 图表规划（需要什么图、什么表）
2. 大纲结构（IMRaD标准）：
   - Abstract（摘要）
   - Introduction（引言：背景→问题→贡献→结构）
   - Related Work（相关工作：按主题分类，指出研究空白）
   - Methodology（方法：设计、数据、算法、分析方法）
   - Experiments/Results（实验/结果：设置、指标、发现）
   - Discussion（讨论：解读、局限性、未来工作）
   - Conclusion（结论）
   - References（参考文献）
3. 保存到 `plan/outline.md`

**门禁：** 用户确认大纲后才能开始写作

---

### Stage 4 — 分章节逐段撰写
**目标：** 按大纲逐章、逐段撰写论文正文

**⚠️ 核心规则（违反即失败）：**
1. **逐段完成并保存** — 不跳过保存与检查；已授权的自动任务保存后继续，不要求每段人工确认。
2. **每写完一个段落立即落盘**，成功后才报告已保存的章节与段落
3. 持续目标运行时结束本轮并由下一轮从磁盘续写；普通对话中等待用户确认后再写下一段
4. **禁止重复说"我在继续""现在开始写"这类话** — 直接写内容，写完就停
5. **段落数量服从论证需要** — 保持逻辑递进，避免堆砌，不用固定段数限制方法和证据的完整表达。

**模型分配：**
- 摘要/引言/相关工作 → gpt-5.6（强推理，构建论证）
- 方法/实验 → claude-sonnet-5（精确描述，防幻觉）
- 讨论/结论 → gpt-5.6（深度解读）
- 润色 → gpt-5.6（文采+准确）

**每段写作流程：**
1. 读取大纲中该段的要求
2. 读取相关文献知识卡片
3. 撰写该段落（200-400字）
4. **两阶段自检：**
   - 阶段一（规范合规）：字数/引用格式/图表编号
   - 阶段二（质量深入）：去AI化/学术表达/引用可追溯/连贯叙述
5. 追加保存到 `chapters/XX-section-name.md`
6. 已授权自动任务继续下一段；交互式逐段审阅或需要真实作者决策时才等待确认。

**章节顺序（严格按此顺序，写完一章再写下一章）：**
1. Introduction（引言）
2. Related Work（相关工作）
3. Methodology（方法）
4. Experiments（实验）
5. Discussion（讨论）
6. Conclusion（结论）
7. Abstract（摘要，最后写）

**去AI化写作标准（强制执行）：**

禁用AI高频词：
| ❌ 禁用 | ✅ 替代 |
|--------|--------|
| leverage | use, employ |
| delve into | examine, analyze |
| comprehensive | complete, thorough |
| multifaceted | complex, multi-step |
| pivotal | key, central |
| notably | specifically, in particular |
| underscores | shows, demonstrates |
| landscape | area, domain |
| showcase | show, demonstrate |
| facilitate | enable, allow |

禁用机械过渡词：firstly, secondly, lastly, moreover, furthermore, in conclusion

禁用防御性语言：to the best of our knowledge, arguably, presumably, it is generally accepted that, one could argue that

写作要求：
- 段落连贯叙述，不使用列表堆砌
- 长短句交替，学术客观表述
- 每个声称必须有引用支撑
- 引用格式统一

---

### Stage 5 — 三视角同行评审
**目标：** 模拟真实期刊审稿，从三个独立视角审查论文

**三名评审人并行审查：**

| 评审人 | 视角 | 审查维度 |
|--------|------|----------|
| Reviewer 1 | 方法论严谨性 | 实验设计、统计方法、可复现性、威胁分析、内部效度 |
| Reviewer 2 | 创新性与贡献 | 新颖性、技术贡献、与现有工作区分、研究意义 |
| Reviewer 3 | 表达与呈现 | 写作质量、图表清晰度、结构逻辑、引用规范 |

**每名评审人执行：**
1. 通读全文，按当前批准范围检查；不把历史目标当作当前肯定结论。
2. 给出有证据和位置的缺陷等级；不估算录用概率，不用主观评分决定科学有效性。
3. 给出具体修改建议（精确到段落/句子）
4. **论文-证据一致性检查：** 每个声称是否有对应数据/引用支撑
5. 给出评审决策：Accept / Minor Revision / Major Revision / Reject

**输出：** `reviews/reviewer-1.md`, `reviews/reviewer-2.md`, `reviews/reviewer-3.md`

**门禁：** 仅已证实的重大科学缺陷触发定点修订；轻微意见和已披露的投稿事项保留为待办，矛盾意见先复核，不整篇反复重写。

---

### Stage 6 — 修改与回应
**目标：** 根据审稿意见修改论文，生成Response Letter

**操作：**
1. 综合三名评审人的意见
2. 逐条修改论文
3. 生成 Response Letter（逐条回应审稿意见）：
   - 意见原文
   - 修改内容（精确到位置）
   - 修改后的文本
4. **R&R可追溯矩阵：** 记录每条审稿意见的处理状态
5. 修订后长度守卫：总词数变化±20%以内

**输出：** 修改后的论文 + `reviews/response-letter.md`

---

### Stage 6.5 — 完整性验证 II（强制门禁，零容忍）
**目标：** 最终深度复查，确保所有问题已解决

**操作：**
1. 重新运行7模式AI故障检查
2. 核实 Stage 2.5 的 SUSPECTED 项；未形成有效审查意见时报告审查异常，真实科学缺陷不能由手动 Override 覆盖。
3. 声明-数据交叉验证：
   - 论文中每个数据声称 → 对应实验/分析结果
   - 论文中每个引用声称 → 对应文献原文
4. 逻辑一致性检查：前后论点是否矛盾

**门禁：** 对真实诚信和重大方法缺陷零容忍；明确区分科学稿件、编辑待办和投稿权限，不以理想结果或零建议作为交付条件。

---

### Stage 7 — 引用终审（四层验证）
**目标：** 确保所有引用真实、准确、格式统一

**四层引用验证：**
1. **存在性验证** — 用 web_search 搜索每篇文献的标题，确认真实存在
2. **元数据验证** — 作者、年份、期刊、卷期页码是否准确
3. **DOI验证** — 如有DOI，验证可解析
4. **格式一致性** — 所有引用格式统一，正文-文献列表双向对应

**操作：**
1. 提取所有参考文献
2. 逐条联网验证
3. 标注：✅真实 / ⚠️存疑 / ❌编造
4. 对编造的引用，搜索并推荐真实的替代文献
5. 修正所有格式问题

**输出：** `reviews/citation-audit.md`

**门禁：** 零编造引用，所有引用格式统一

---

### Stage 8 — 格式化与输出
**目标：** 生成最终交付物

**操作：**
1. 合并所有章节为完整论文
2. 按目标期刊格式排版
3. 生成摘要（中英文）
4. 生成关键词
5. 生成AI使用声明（如需要）
6. 输出格式：
   - Markdown 源文件
   - DOCX（用 pandoc 转换）
   - PDF（如环境支持）
7. 保存到 `output/`

---

### Stage 9 — 最终审核与交付
**目标：** 最终检查，交付完整成果

**交付清单：**
- [ ] 完整论文（Markdown + DOCX）
- [ ] 参考文献列表（已验证）
- [ ] 大纲文档
- [ ] 文献综述与知识卡片
- [ ] 三视角审稿报告
- [ ] Response Letter
- [ ] 引用审计报告
- [ ] 完整性验证报告

## 重要规则（不可违反）

1. **绝不编造参考文献** — 找不到就不引用，或明确告诉用户需要补充
2. **绝不虚构实测** — 数值计算、经验假设和生成输入必须分别标识并可追溯，不能冒充现场测量；失败、未知和空结果必须保留。
3. **每个声称必须有证据** — 引用或数据支撑，否则标记为"待验证"
4. **门禁不可跳过** — Stage 2.5 和 6.5 是强制完整性验证，不通过不推进
5. **引用必须可追溯** — 每条引用都能通过搜索验证
6. **如实报告问题** — 发现编造引用或逻辑漏洞时明确指出，不隐瞒
7. **用户掌握研究决策权** — 研究问题、方法论选择、结果解读由用户决定
