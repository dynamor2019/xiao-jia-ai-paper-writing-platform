# Corpus Memory

使用 `research_memory` 减少重复读取和重复注入全文。记忆是文件哈希绑定的派生索引，不替代原始证据。

## 强制顺序

1. 在读取任何曾经接触过的语料文件前，先调用 `research_memory` 的 `lookup`。
2. 返回 `MEMORY HIT` 时直接使用摘要、证据点和引用键；不得再次读取原文件。
3. 返回 `MISS` 时只读取完成当前任务所需的最小范围，然后立即调用 `store`。
4. 返回 `STALE` 时说明文件哈希已变化；重新读取一次并覆盖旧 memo。
5. 不知道证据在哪个文件时先使用 `search`，不得依次打开全部语料碰运气。

## Memo 内容

- `summary`：只保留研究问题、适用范围和与当前项目相关的结论。
- `keyEvidence`：每条包含主张、数值或结论及页码/章节/表图等定位信息。
- `methods`：样本、数据、模型、比较基线和关键设置。
- `limitations`：作者承认的限制、外推边界和证据冲突。
- `citationKeys`：DOI、作者年份、文献编号或本地引用 ID。
- `keywords`：可供后续 search 命中的稳定术语和同义词。

不要把全文、长段原文或整张参考文献表复制进 memo。一个来源的 summary 应尽量控制在 800 字以内；证据点要短而可定位。

## 上下文恢复

压缩、重启或切换阶段后，先 `list` 或按当前小节 `search`，只恢复当前论证需要的 memo。正文衔接使用已经保存的段落摘要，不重新加载整个 manuscript。遇到引用争议、精确数字或原文措辞时才回到原始文件核验，并在核验后更新 memo。
