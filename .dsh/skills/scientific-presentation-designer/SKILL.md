# Scientific Presentation Designer

先加载 `univer`、`univer-slide`；涉及实验图表时同时加载 `scientific-figures-tables`。本 skill 决定视觉与叙事，Univer skills 负责可靠写入、检查和导出。

## 交付原则

- 先形成故事线，再画页面；不把论文段落直接搬到幻灯片。
- 每页只承担一个可复述的结论，标题优先写成结论句，而不是章节名。
- 数据、方法结构、对比关系和证据应成为页面主体；装饰不能替代信息。
- 保留可编辑文字、图表和结构。照片、复杂插画和 Logo 才使用位图。
- 不使用大段项目符号、无意义卡片阵列、连续同构页面、Emoji 占位符或装饰性 3D 图表。

## 开始前

在 workspace 写入 `deck-brief.md`，至少固定：

1. 受众、场景、时长和最终行动目标。
2. 一句话研究问题、一句话方法、一句话主要发现。
3. 必须出现的数字、图表、案例、限制和引用。
4. 页面比例、语言、目标页数或时间约束。
5. 从 [主题系统](references/themes.md) 选择的主题及其完整色值和字体角色。

根据场景读取 [叙事结构](references/storyboards.md)，写逐页 storyboard。每页记录 `page | message | evidence | visual | source | status`。缺少来源的数据不得进入视觉稿。

## 页面设计

- 使用 16:9、960 x 540 画布，默认安全边距不少于 44 px，建立一致的标题线、内容区和页脚线。
- SVG 标题通常为 32-42 px，正文 18-24 px，注释 13-16 px；同一层级全篇一致。文本过多时删减或拆页，不缩成不可读字号。
- 优先使用非对称网格、明确视觉锚点和有方向的阅读顺序。相邻页面不得连续复用同一结构。
- 每页至多一个主要视觉焦点；小图标只用于分类或导航，不作为内容填充物。
- 用颜色表达类别或强调，不能只靠颜色表达数据差异。全篇主色、强调色和语义色含义固定。
- 结果页直接标注关键数值、基线和不确定性；不要让观众从密集图例中自行寻找结论。
- 方法页优先使用流程、系统结构、输入输出或因果链；Related Work 优先使用定位图、分类矩阵或时间线。
- 引用放在相应页面底部，使用短格式并保留 DOI、作者年份或可追溯编号。

## 视觉资产

先调用 `univer_resources` 查找并导出统一风格的图标、Logo 或插画。实验图必须来自可追溯的数据和脚本。可用图像生成工具时，只生成有明确语义的概念图或封面视觉，并把最终资产保存到 workspace；没有可用工具时改用数据图、流程图或排版，不留占位符。

外部 Canva 或 Gamma 连接器只能用于获取已授权素材或参考布局，不能绕过 Univer worktree、数据追溯和视觉校验，也不能声称已调用尚未连接的服务。

## 构建闭环

1. 调用 `univer_status`，确认目标 Unit 和当前 `draft` worktree。
2. 每页先完成 `page-NN.svg`，再使用 `univer_compile_svg` 的 `replace` 模式写入。
3. 编译后立即运行无 range 的 `univer_inspect` 和该页 `univer_lint`。
4. 每完成至多五页，调用 `univer_screenshot` 获取逐页 PNG；contact sheet 只能作为总览。
5. 加载 `slide-visual-qa`，根据截图给出 PASS/FAIL；任何 FAIL 必须回到 SVG 源文件修正并替换页面。
6. 全篇通过后才进入 `ready`，然后按用户要求导出 PPTX。不得跳过截图审查或把成功导出视为视觉通过。

## 完成标准

最终必须保留 `deck-brief.md`、逐页 SVG、来源清单、逐页截图和 `slide-visual-qa.md`。只有结构检查、布局 lint、逐页视觉审查和跨页一致性全部通过，才可以称为完成。
